# SMS Login Replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every QR login path with owner-operated +86 SMS login and manual official CAPTCHA, preserving game/community sign-in and old credentials on failed replacement.

**Architecture:** Independent Node ESM protocol adapter, in-memory SMS flow state machine, thin integration into MysService, and the existing React client panel. All upstream requests use guarded host HTTP; CAPTCHA scripts execute only in an opaque sandbox iframe. Persist the successful candidate through the existing StateStore only after required read-only checks.

**Tech Stack:** Node >=22, built-in crypto/fetch/node:test, existing DSH Host/Client APIs and React ModuleLoader; zero runtime dependencies or new build step.

**Spec:** [Approved design](../specs/2026-11-18-sms-login-design.md)

## Review Focus

1. Cancel/new flow/logout/dispose during any await must suppress all subsequent dispatches and credential writes; Task 2/3 deferred-fetch tests.
2. Duplicate submit, canceled-flow resend and unknown POST outcome must not send duplicate SMS or reset the cooldown; Task 2 state-machine tests.
3. HTTP 200 + nonzero retcode + data:null, malformed nested CAPTCHA and unsafe tokens must produce bounded safe errors, never false success or leaks; Task 1 protocol tests.
4. Wrong flow/nonce/window/source, stale or oversized GT3/GT4 results must not continue a host request; Task 2/4 bridge tests.
5. Empty game-role lists are legitimate, malformed success envelopes are not; community-disabled query failures cannot be relabeled game expiration; Task 3 candidate-acceptance tests.
