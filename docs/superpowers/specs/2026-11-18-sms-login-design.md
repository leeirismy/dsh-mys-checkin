# 短信登录替换扫码登录设计

日期：2026-11-18（Asia/Shanghai）
状态：用户已批准按此设计执行；未授权发送真实短信、登录或签到。

## 意图与已确认决策

用户要求参考 IKUNHEIHIE/miyoushe-checkin，以短信登录替换插件扫码登录，并先清理此前提交。用户已选择清理整段 SDK 与诊断提交：以 e988b41 为基线，新分支不包含 e3d3f72 至 ad38225 的 9 条提交；保留旧历史备份，主分支验收前不动。保留游戏签到、米游币社区签到、现有设置和调度策略。

## 方案取舍

采用：在现有零运行时依赖的 Node ESM 宿主与侧边栏中独立实现短信协议，替换所有扫码入口；此实现方式为工程侧提议，随本文一并请求批准。

不采用：保留扫码作为兜底，会继续维护用户明确要替换的故障链；部署参考项目的独立后端，会引入另一套服务、账户存储与运维；只导入网页 Cookie，不能完整满足社区 SToken 和后续凭据派生需求。

参考项目仅提供公开协议字段和作者的有限实测依据，不直接复制未核实许可的实现。原神社区和原神/星铁/绝区零的作者单账号记录不等于本插件已经实测。

## 范围与非目标

- 面板改为手机号、发送验证码、验证码输入、登录、取消和状态提示。首版只支持中国大陆 +86 手机号；不增加多账号功能。
- 游戏签到和米游币社区签到共用一套短信登录，登录方式不再受社区开关影响。
- 支持登录链中的官方极验 GT4/GT3 用户手动验证；其他实名、真人或账号恢复要求停止并提示官方处理。
- 不增加阅读、点赞、分享、发帖、自动解验证码、第三方打码或规避风控。
- 签到阶段原有验证码行为保持“停止并提示”，不在本次扩展为签到验证码续跑系统。
- 不改变游戏与社区执行范围、日期隔离、调度窗口、已有防重复写入策略。登录验收只执行只读查询，不自动签到。

## 用户流程

```text
短信登录
手机号（+86） [发送验证码]
  若官方要求验证 → 用户完成官方验证 → 仅续接对应请求
短信验证码   [登录] [取消]
  登录 → 获取 SToken → 派生工作凭据 → 只读校验 → 保存新登录
```

发送、登录期间禁用重复点击；显示官方返回的重发倒计时。明确区分等待人工验证、验证码已发送、验证码错误/过期、限流、请求结果不明、会话过期、只读验证失败和成功。不因 HTTP 200 就显示发送或登录成功。关闭、取消或流程过期后，旧异步响应不得重新打开界面或提交账号。

## 协议和身份边界

1. 宿主以 RSA PKCS#1 v1.5 加密 +86 和手机号，POST 官方 createLoginCaptcha；保存返回的 action_type 与冷却时间。
2. 用户主动提交短信验证码后，POST loginByMobileCaptcha，携带同一流程的设备上下文和 action_type。
3. 严格校验 token_type=1、非空安全的不透明 SToken、数字字符串 aid 和安全 mid；不依赖令牌固定长度。
4. 使用该次登录的 stuid/stoken/mid，GET getLTokenBySToken 与 getCookieAccountInfoBySToken；验证工作 Cookie 的 uid 与登录 aid 一致。不能拼接旧账号、其他流程或浏览器传入的令牌。
5. 以本次派生凭据做游戏账号只读验证及米游币任务状态只读查询；未启用社区时也取得完整根凭据，但不把社区查询临时失败伪装成游戏凭据失效。具体保存判定：游戏验证和凭据账号一致性必需；已启用社区时社区查询也必需，未启用时社区查询失败只显示未确认社区能力，不声称社区已验证。
6. 社区查询使用最小 account_id + cookie_token，社区签到继续使用最小 stuid + stoken + mid。任务状态查询只能证明请求凭据获受理，不能单独作为 UID 身份证明；UID 一致性依据登录响应与凭据交换结果，不使用公开 UID 资料来认证。
7. 去掉旧 SDK 候选的无 UID getUserFullInfo 硬门槛；昵称/头像获取最多为非关键只读补全，不影响成功，也不能覆盖安全错误。
8. 不复用旧 SDK 参数或网页登录兜底。请求头按短信参考协议实现，设备值在一个流程内稳定，不虚构 device_fp。成功后把对应设备上下文与账号绑定用于后续凭据交换；不随意重置已保存的 BBS 设备 ID。

候选凭据在所有必要步骤成功后才原子替换旧登录。派生工作 Cookie 不是根 SToken 续期，不宣称永久免登录。

## 手动人机验证与隔离

- 优先识别官方 x-rpc-aigis（包括 -3101 携带验证配置的情况），解析经过长度、类型与字段白名单校验的 GT3/GT4 配置；不只按“请求频繁”文案重试。
- 官方 session_id、设备、原请求步骤与本地随机流程 ID 在宿主内绑定。浏览器仅取得渲染所需的公开配置与本地 challenge ID，不取得 SToken、Cookie 或官方原始响应。
- 使用限制权限的 sandbox iframe 加载固定 HTTPS 官方极验组件。父页校验消息 source、一次性随机 nonce、消息类型与结果字段；不把外部脚本直接注入 DSH 主页面，不允许任意脚本 URL、任意导航或任意代理地址。具体 CSP/组件兼容性需在现有 GUI 中验收，不能用 mock 成功冒充实际兼容。
- 验证结果仅用于绑定的待续接请求，由宿主按官方格式构造 x-rpc-aigis。验证失败由用户重新操作；不得无限重试，也不把刷新组件当作发送新短信或延长官方会话。
- 不支持的验证类型或组件加载失败必须明确停止，不静默降级。

## 服务、数据和安全

- 以宿主登录状态机替换二维码轮询：创建流程、主动发送短信、主动提交验证码、主动提交人工验证、取消；状态 GET 仅查询内存，不触发上游写请求。
- 流程仅存内存，使用不可预测 ID、明确过期时间、倒计时、每步互斥与代际校验。注销、取消、创建新流程、宿主释放后，过时请求不能继续发起后续网络请求或覆盖认证。
- 短信发送和登录 POST 均关闭传输自动重试；结果不明时提示用户，不自行重发。验证码错误后允许在同一有效流程内由用户重新输入；限流遵守冷却，重发成功替换对应 action_type，防止旧码和旧上下文混用。
- 保留 owner-only 路由保护；短信相关写操作仅接收受限大小的 JSON，检查同源来源，验证输入及当前流程归属。日志、错误、URL、状态和公共诊断中不得出现手机号、验证码、令牌、Cookie、官方验证 session_id 或原始上游响应。手机号只在输入和必要流程内存在，公共状态最多展示脱敏值。
- 登录口令、完整手机号和人工验证结果不写磁盘、不使用浏览器持久化；沿用插件现有账号凭据存储边界，本次不额外开展凭据存储系统迁移。实现及测试不得读取、打印或改写生产账号状态。
- 错误仅暴露固定分类和受限诊断 stage/httpStatus/retcode；不返回任意上游文案、请求头、请求体、异常堆栈或完整 URL。
