状态：已于 2026-11-18 经用户回复“开始”批准；实施计划及当前会话实施方式亦已确认。不授权真实接口测试。

## 1. 意图与已确认范围

在本地 `@local/dsh-mys-checkin` 中增加米游社社区签到，与已有游戏签到共存。
用户已选择：第一版只做社区签到；分区可多选，默认社区 5 与 2（大别野、原神）。之前对话称“大别墅”，实现采用参考仓库的“大别野”名称，ID 不变。

目标：复用扫码登录、随机定时窗口和现有面板；支持单独手动社区签到；展示每分区签到结果，以及可查询到的账号米游币信息。
不做：看帖、点赞、取消点赞、分享、发帖、自动解验证码、Python 子进程、多账号管理、新增独立定时窗口。
反目标：社区操作吞掉游戏定时机会、覆盖游戏结果、泄露凭据、默认新增账号写行为、把请求不明误报成功。

## 2. 实现方式

工程建议（由昔涟提出）：原生 JavaScript ESM，新增社区协议模块，扩展现有 service/store/client。复用 Node 内建能力，不新增运行时依赖。

比较过的方式：
- 原生模块：最契合已有认证、测试和部署方式，推荐。
- 调用 Python 仓库：引入 Python 环境、第二套凭据/配置和重试策略，不采用。
- 直接塞进游戏数组：社区没有游戏角色/活动 ID，且结果结构不同，不采用。

用户已确认功能范围、默认分区、原生 JavaScript 工程方式及下述行为；后续实施采用已确认的当前会话实施方式。

## 3. 配置与用户操作

新增 `community` 配置：
- `enabled: false`：升级后默认关闭，由用户主动开启；启用后随现有定时窗口运行。
- `gids: ['5', '2']`：白名单多选、去重；顺序稳定。提供崩坏3、原神、崩坏学园2、未定事件簿、大别野、星铁、绝区零这七个分区。
- 社区专用 App 版本和 DS2 salt 使用参考代码参数作为初始兼容配置，不改游戏 `client` 参数；允许在 Host 配置中覆盖，不新增首版高级 UI。

开启但未选择分区时展示配置错误，不静默回填默认或调用接口；缺失字段的旧配置补默认。

面板草图（沿用现有视觉，不做重设计）：

    社区签到 [开关]
      签到分区：大别野 ✓  原神 ✓  星铁 □  …
      [立即社区签到]（仅在启用、有分区、凭据可用且空闲时可用）

社区开关只控制社区；原游戏执行按钮仍只控制游戏；自动运行才组合两个已启用范围。关闭总定时开关不禁止现有手动操作，社区开关关闭时则不执行社区写请求。
新增 owner-only 社区执行入口，复用现有 route 注册/返回格式；状态响应新增 `community`，不返回 Cookie、SToken、mid 或原始接口响应。后台严格校验启用状态与分区，不能只依赖按钮禁用。

## 4. 协议、认证与结果语义

新增 `lib/community.js`，负责最小凭据构造、请求头、查询与签到结果归一化。
- 使用已有 `sessionStoken()` 读取令牌，出站 Cookie 使用 `stuid`、`stoken`，V2 必须有 `mid`。本地保存为 `stoken_v2` 不影响出站名称。
- 从已保存的规范化账号字段/别名解析 ID，不读取额外凭据文件，不让凭据进入前端或日志。
- 缺 SToken 或 V2 缺 mid：社区状态为不可用，提示重新 App 扫码；游戏登录状态不受影响。
- 现有 refreshCredentials 只换取 ltoken/cookie_token，不是刷新 SToken；不能把它当作修复无效社区 SToken 的方式。
- 社区请求采用参考 App 头（client_type 2、设备 ID、verify_key 等）；签到为 `POST https://bbs-api.miyoushe.com/apihub/app/api/signIn`，body `JSON.stringify({gids: id})`（字符串 ID），使用 DS2 x6 对实际发送的同一个 body 字符串签名。
- 社区专用初始 appVersion 为 `2.117.0`，DS2 salt 为 `t0qEgfub6cvueAPgR5m9aQWWVciEer7v`；这些仅来自本地参考源码，未验证当前线上兼容性。第一版无需 DS1 社区操作。
- 余额/任务查询为 `GET /apihub/wapi/getUserMissionsState?point_sn=myb`，按参考实现使用普通账号 Cookie，不额外签 DS。只提取白名单数值字段，不携带原响应进入状态。

每次社区运行：检查能力 → 查询一次账号信息 → 串行签到所选分区 → 查询一次账号信息 → 保存结果。已在本账号/业务日明确成功的分区可本地跳过；余额查询失败不阻止签到，除非返回明确风控信号。签到之间复用配置间隔，不为绕过风控添加机制。

任务 58 等属于账号级任务进度，不能证明每个分区已签，更不能用 `can_get_points == 0` 跳过所有所选分区。余额变化只作账号快照，不宣称全部由本插件获得，也不承诺积分数量或每日上限。

结果分类：success、cached-success、captcha、auth-unavailable、expired、error、unknown、skipped。离线验收采用最小返回契约：HTTP 2xx、可解析的非数组 JSON 对象、数字类型 `retcode === 0`；`message` 可缺失，存在时应为字符串；`data` 可缺失或为 null，存在且非 null 时应为非数组对象。不臆造社区 signIn 必须返回的积分/签到天数字段。已识别的风控信号优先于成功；超出上述结构或存在无法解释的验证要求时记 unknown。success 仅表示接口返回接受成功，不等价于独立验证积分到账。测试响应明确标注为人工构造的契约夹具，不冒充真实抓包；线上兼容性留作单独授权的验证项。“已签到”非零码仅在有社区专属证据后加入白名单，不能照搬游戏的 -5003 或靠 message 子串猜测。未知码保留数值和安全消息为失败，不报成功。

SToken 明确失效只标记社区错误，不删除共享凭据或覆盖游戏登录状态。验证码（包括参考 1034）停止本轮后续写请求，提示手动处理；不调用 createVerification 或任何解码服务。

社区 POST 显式 `retries: 0`，不套用游戏 signWithRetry。传输超时、非 JSON、结构异常、HTTP 异常导致结果无法确定时记 unknown，本轮不重发；下一次手动或隔日可重新尝试。任务回查只是补充信息，不能凭账号级任务反推不明分区的成功。

## 5. 状态、调度与换号安全

增量扩展状态，避免无关的游戏全量重构：
- 保留既有游戏 lastResult/lastError/日期契约，新增 `runtime.community`，含账号绑定标识、业务日期、所选分区快照、分区结果、最近运行时间、余额快照及快照查询时间/错误。
- 新增明确的自动调度尝试日期字段，与手动 scope 结果分开。初始化、序列化和 migrate 都要覆盖新增字段；旧版本 lastRunDate 保守迁移为当天已消费的自动尝试标记，防止升级当日重复自动运行。
- 账号绑定仅使用公开数字账号 ID，不保存额外密钥。无法确定账号 ID 时社区功能不可用。

只有一个调度器、一个共享执行锁。自动运行根据游戏/社区启用情况组合目标；没有任何游戏仍可执行社区。普通单个范围失败不覆盖另一范围结果；风控停止本轮余下写操作，未执行项目标为 skipped，不标签到成功。

调度规则：
1. 总开关和现有窗口/时区继续控制自动运行。
2. 自动尝试在成功取得执行锁且确有可运行目标后记为已尝试；匿名跳过也记录自动跳过，避免持续补跑。因 busy 未开始时不消费当天机会，在当前任务结束后重新规划。
3. 自动运行每天最多一次尝试，不因余额读取失败或社区失败反复触发补跑。
4. 手动社区运行只更新社区状态，不更新游戏日期或自动尝试日期；手动游戏仍只更新游戏范围。
5. 若两个已启用范围均在当前调度日手动完整成功，planner 可以视为今日完成；仅一个范围成功时不能抑制另一个范围的自动机会。自动组合执行时可跳过该范围当天已明确完成的目标，但必须保留历史结果。
6. 区分尝试和成功，失败的范围在后续手动执行中仍可重试。

自动日期沿用用户配置时区；社区分区签到的去重业务日固定 `Asia/Shanghai`（国内社区），持久化时间戳及业务日。跨午夜不沿用上一业务日分区成功缓存；每次请求前重算业务日，查询前后跨日时不计算积分增量。避免将两个日界线混成一个标记。

退出/换号清除或失效账号绑定的结果及每日消费信息，重新规划；所有异步任务持有账号会话 generation。每次请求前、等待后、持久化前验证 generation，变化即停止后续请求并丢弃旧结果。已发出的请求不能撤销，不承诺取消成功；旧任务不可将结果/凭据写给新账号。该保护覆盖原游戏任务与现有续期回写，避免共享锁下的交叉污染。配置运行时使用开跑快照；关闭社区后不再发起后续社区写操作。

## 6. 安全与兼容边界

- 复用现有 owner-only Host 注册机制，不新增绕过认证入口。
- 日志与错误只输出固定接口名、分区、结果码及经截断/脱敏的消息，不输出完整 URL、Cookie、响应对象或令牌。
- 存储沿用现有私有目录和原子写；单进程锁不等于跨实例锁。首版不新增多实例自动运行保证，说明不可多个 DSH 实例同时操作同一账号。
- 不升级依赖，不修改 profile 链接，不自动重启 DSH。功能生效所需的 Host 重载/重启在实施验证后单独说明。
- 不扩大现有 Client 包运行时导入；沿用本地 fallback 控件与主题变量。
- 移植实质参考代码时保留其 MIT 版权声明。

## 7. 验证与交付边界

开发阶段只允许 fake fetch、临时 DSH_HOME 和纯函数测试，不读真实状态、不发真实请求；mock 未匹配请求必须直接失败，不能回落真实网络。

验收测试至少覆盖：
- 默认关闭与默认分区，白名单/空列表校验，旧配置/旧状态迁移和重启恢复。
- V1/V2 Cookie、缺 SToken/mid、签名 body 字节一致、POST 无自动重试。
- 分区串行、部分失败、查询失败不掩盖成功、账号任务不被当分区证据、未知 retcode/非 JSON/超时不报成功。
- 验证码停止后续写操作，社区过期不清共享游戏登录，脱敏。
- 全关游戏仍可社区；手动社区不消耗游戏机会；两个范围结果独立；自动每日最多一次、busy 不吞机会、已成功分区跳过。
- 调度时区与上海业务日、跨午夜、换号/退出时在途请求不得继续或回写。
- 新增测试纳入 CI，原四组测试保持通过；检查界面可访问性、空态和部分失败显示。

静态/单元测试通过只代表实现验证，不代表线上协议可用。真实账号冒烟与真实社区签到需用户另行明确授权；GUI 无可用浏览器控制时清楚列出未验证项，不宣称实机界面验收通过。
